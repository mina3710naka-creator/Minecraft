# フックショット (Hookshot) — Minecraft データパック

釣り竿を右クリックすると、視点方向へ**透明な防具立て（フック）**が飛んでいき、
壁や床、あるいは MOB に当たるとそこに**マーカーが固定**され、プレイヤーが
**滑らかに引き寄せられる**ワイヤーアクション用データパックです。

---

## 動作の流れ

| 順番 | 処理 |
| --- | --- |
| 1 | 釣り竿を使うと、まず**自分が出した釣り針（fishing_bobber）をキル**する |
| 2 | **透明な防具立て**（フック）を視点方向へまっすぐ射出（1 tick に 5 ブロック / 最大 100 ブロック） |
| 3 | 防具立てとプレイヤーの間に**リード**を張り、**キラキラ（end_rod / glow）のロープ**を描画 |
| 4 | 壁や床に着弾すると、その位置に**マーカーが固定**される。**MOB に着弾した場合はその MOB にアンカーが追従**し、MOB が動けば向きを変えながらそちらへ引き寄せられる |
| 5 | 見えない台車（コウモリ）にプレイヤーを **ride で乗せ**、台車の方だけを
    **フックと同じ tp ステップ方式で**（最高 4.0 ブロック / tick）マーカーへ、ぎりぎりまで引き寄せる |
| 6 | **マーカーに到達**したら、台車を即座に片付け、**レビテーション（浮遊効果）**でプレイヤーを上に約 5 マス打ち上げてから解除 |
| 7 | 到達しないまま**3 秒（60 ティック）引き寄せられた**場合は、打ち上げずそのまま自動で解除 |

* 引き寄せ中にもう一度釣り竿を使うと、その場で解除できます（トグル）。
* 100 ブロック飛んでも何にも当たらなかった場合は自動で解除されます。

---

## 導入方法

1. このリポジトリの `hookshot` フォルダを、ワールドの `datapacks` フォルダにコピーします。

   ```
   .minecraft/saves/<ワールド名>/datapacks/hookshot/
   ├── pack.mcmeta
   └── data/
   ```

   （サーバーの場合は `<サーバーフォルダ>/world/datapacks/hookshot/`）

2. ワールドに入って `/reload` を実行します。
   チャットに `[フックショット] 読み込み完了` と表示されれば成功です。

3. アイテムを受け取ります。

   ```
   /function hookshot:give
   ```

4. 受け取った釣り竿「フックショット」を持って右クリック。

> 通常の釣り竿はそのまま釣りに使えます。フックショットが発動するのは
> `custom_data` に `hookshot` が付いた専用の釣り竿を持っているときだけです。

### 旧バージョン（1.21.x）で使いたい場合

`pack.mcmeta` は 26.2 向けに `min_format` / `max_format` を使っています。
1.21.9 より前では読み込めないので、次の 3 点を戻してください。

1. `pack.mcmeta` を `"pack_format": 48, "supported_formats": {"min_inclusive": 48, "max_inclusive": 88}` に戻す
   （`min_format` / `max_format` は 1.21.9 以降専用、`supported_formats` は 1.21.9 以降では使えません）
2. リードのサウンドを旧 ID に戻す
   （`pull/start.mcfunction` の `item.lead.tied` → `entity.leash_knot.place`、
   `release.mcfunction` の `item.lead.untied` → `entity.leash_knot.break`）
3. アイテム配布は `/function hookshot:give_old`（1.21.4 以前の JSON 文字列表記）を使う

### アンインストール

```
/function hookshot:uninstall
```
を実行してから、データパックのフォルダを削除してください。

## 調整できる数値

| 内容 | ファイル | 該当箇所 |
| --- | --- | --- |
| フックの速さ | `hook/tick.mcfunction` | `scoreboard players set @s hs.sub 20`（1 tick のステップ数 × 0.25 ブロック＝5.0 ブロック / tick） |
| フックの射程 | `hook/step.mcfunction` | `hs.range matches 400..`（400 × 0.25 = 100 ブロック） |
| MOB への着弾判定範囲 | `hook/step.mcfunction` | `@e[...] distance=..3`（進行方向の点から 3 ブロック以内なら自動吸着） |
| 台車（引き寄せ）の初速 | `pull/carrier_init.mcfunction` | `hs.spd 120`（= 1.2 ブロック / tick） |
| 加速度・最高速度 | `pull/tick.mcfunction` | `add @s hs.spd 60` / `matches 400..`（= 4.0 ブロック / tick） |
| 減速ゾーン | `pull/move.mcfunction` | `distance=0.2..4` → 0.6、`distance=4..8` → 1.2 ブロック / tick に制限 |
| 引き寄せの制限時間 | `pull/tick.mcfunction` | `hs.pt matches 60..`（60 tick = 3 秒） |
| 到達とみなす距離 | `pull/move.mcfunction` / `pull/step_continue.mcfunction` | `distance=..0.2`（マーカーのぎりぎりまで近づいてから打ち上げる） |
| 到達時の打ち上げの高さ | `pull/launch.mcfunction` / `pull/launch_tick.mcfunction` | `effect give ... levitation 4 23 true`（amplifier）／ `hs.lt matches 7..`（効果を切るまでの tick 数） |
| 通り抜けるブロック | `data/hookshot/tags/block/passable.json` | 草・水・松明などフックが貫通するブロック |
| 落下ダメージ無効化（解除後） | `release.mcfunction` | 最終行の `effect give ... slow_falling` のコメントを外す |
| 対応バージョン範囲 | `pack.mcmeta` | `min_format` / `max_format`（26.2 = 107） |

## 実装メモ

* **プレイヤーを直接 tp せず、見えない台車に乗せて台車を tp する** —
  バニラのコマンドでは、実在する**プレイヤー**の `Motion`（速度）NBT を
  書き換えることはできません。かといって、プレイヤー自身を毎ティック
  直接 `tp` すると、クライアント側の予測処理とサーバーからの位置修正が
  ぶつかり合ってカクついて見えてしまいます。
  そこで本パックは、見えない**台車（コウモリ）**を着弾と同時に出現させ、
  `/ride` コマンドでプレイヤーをその台車に乗せます。**動かすのは台車の
  方だけ**（フックの飛行と同じ `tp` ステップ方式）で、プレイヤーは
  ただ乗っているだけです。乗り物に乗っている間の位置追従はゲーム側の
  仕組みで滑らかに補間されるため、プレイヤー自身を直接 tp するより
  カクつきにくくなります（乗っている間、WASD 等の自力移動は効きません。
  視点操作はプレイヤー自身が自由に行えます）。
  * 台車には防具立てではなくコウモリ（`NoAI` で自力飛行だけ止めたモブ）を
    使っています。台車自体は見えないので、`tp` で座標・向きを書き換えても
    見た目に違和感はありません。実体としての当たり判定も持っているので、
    仮に手動の判定をすり抜けても壁の中に入り込みにくい、という保険にも
    なっています。
  * 台車の 1 tick 分の移動は 8 分割し、フックの飛行（`hook/step.mcfunction`）
    と全く同じ考え方で、**細かいステップごとに着弾判定をしてから進みます**
    （`pull/move.mcfunction` / `pull/step.mcfunction`）。最高速度は 4.0
    ブロック / tick（フックの飛行速度とは別に調整可能）まで出るので、8
    分割すると 1 ステップ最大 0.5 ブロックになりますが、それでも十分な
    精度で着弾判定できます。壁や床にぶつかればその場で切り離されるので、
    めり込みは起こりません。
  * 速度を毎ティック少しずつ加算（イーズイン）し、着弾点に近づくと段階的に
    減速する（イーズアウト）ため、動き出しも止まる瞬間も急になりません。
  * **マーカーに到達すると、台車をすぐに片付け、レビテーション（浮遊効果）
    でプレイヤーを上に打ち上げます**（`pull/arrive.mcfunction` /
    `pull/launch.mcfunction` / `pull/launch_tick.mcfunction`）。
    * 最初は `damage <対象> <量> <種別> at <座標>` で爆発扱いの
      ノックバックを与える方式にしていた（地形に依存せず確実に着弾
      させられる、という利点があったため）。ただし `minecraft:absorption`
      でダメージを吸収させるとノックバックそのものも一緒に無効化されて
      しまう問題があり、ダメージを与える直前に体力を一時的に 100 まで
      底上げしてから本物のダメージを通し、直後に元の体力へ戻す、という
      回避策が必要だった上に不安定だった。
    * 最強のブーツ（`opboots`）の 10 マスジャンプ（`jump/leap.mcfunction`）
      が全く同じ問題（耐性エンチャントがノックバックごと無効化する）を
      レビテーションで解決していたため、同じ手法に切り替えた。ダメージや
      体力操作を一切伴わない純粋な効果による移動なので、確実に働く。
    * `pull/launch.mcfunction` でレビテーション（amplifier 23、opboots と
      同じ値）を付与し、`pull/launch_tick.mcfunction` が毎 tick カウントして
      指定 tick 数（現在 7）で効果を切り、あとは通常の重力に任せて落とす。
      上昇量は tick 数で決まるので、厳密に 5 ブロックとは限らない。高さを
      変えたい場合は `pull/launch_tick.mcfunction` の tick 数を調整する。
    * 3 秒経過による解除（到達できなかった場合）では打ち上げは
      発生しません。
  * 解除時は台車をすぐに死亡演出（音・パーティクル）なしで消します
    （`pull/launch.mcfunction` / `release.mcfunction` /
    `util/cleanup.mcfunction` / `util/quiet_kill.mcfunction`）。
  * **既知の制約（バニラの仕様上、コマンドでは解消できません）** —
    生物（モブ・防具立て）に `/ride` で乗っている間は、バニラの仕様として
    ①満腹度バーの位置に**台車の HP バー**が表示される、②プレイヤーが
    **座りポーズ**になる、という 2 点が必ず起こります。台車は無敵
    （`Invulnerable:1b`）で常に満タン表示のままなので実害はありません。
  * ちなみに、当初は台車の `Motion`（速度）を直接書き換えて動かす方式を
    試しましたが、**乗られている（ride されている）モブは `Motion` を
    書き換えても実際には動かない**ことが分かったため、この tp ベースの
    方式に変更しています。
* **MOB 追従アンカー** — MOB に着弾した場合、`minecraft:marker` ではなく見えない
  コウモリ（`hook/anchor_init_mob.mcfunction`）をアンカーとして生成し、`ride`
  コマンドでその MOB に乗せている（`hook/anchor_to_mob.mcfunction`）。
  * `marker` エンティティは乗り物に乗ることができない仕様のため、着弾地点に
    固定する（動かない）場合は従来通り `marker` を使い、MOB に追従させたい
    場合だけ、台車やリードのアンカーと同じ「見えないコウモリ」に切り替えている。
  * 乗り物に乗った状態の位置追従はゲーム側の仕組みで毎ティック自動的に処理される
    ため、MOB が動いても、こちらから座標を書き換え直す必要はない。引き寄せ側
    （`pull/move.mcfunction` 等）はアンカーの座標を毎ティック参照しているだけ
    なので、アンカー自体が MOB に追従してさえいれば、向きを変えながらの
    引き寄せは特別な対応なしに成立する。
  * MOB が死亡するとアンカー（コウモリ）は自動的に降ろされ、その場に取り残される
    ため、以降は着弾地点固定と同じ挙動（最後にいた位置へ向けて引き寄せ）になる。
* **リードの NBT** — エンティティに繋ぐ場合の書式は `leash:{UUID:[I;...]}` です
  （フェンスに繋ぐ場合は `leash:[I;x,y,z]`）。そのため
  `data modify entity @s leash.UUID set from entity <プレイヤー> UUID` と、
  `leash` 直下ではなく `leash.UUID` に書き込んでいます。
* **リードについて** — バニラのリードは約 10 ブロックで切れてしまうため、
  リードを結ぶ見えないコウモリ（`NoAI` / 無敵 / 透明）はプレイヤーとフックを結ぶ線上の
  最大 8 ブロック地点に留まるようにしています。そこから先はパーティクルのロープが繋がります。
* **エンティティの後始末** — フック・マーカー・ロープには共通タグ `hs.ent` が付いており、
  12 秒経過したものや `/reload` 時に残っていたものは自動で削除されます。
* リード用のコウモリは `/kill` すると死亡演出とリードのドロップが発生するため、
  解除時は奈落へ飛ばして静かに消滅させています（念のためドロップしたリードも掃除します）。
* 使用検知には統計 `minecraft.used:minecraft.fishing_rod` を使っており、毎ティック 0 にリセットします。
  そのため「釣り竿を使った回数」の統計は増えなくなります。
* 26.x でリード関連のサウンド ID が変更されました
  （`entity.leash_knot.place` / `.break` → `item.lead.tied` / `item.lead.untied` / `item.lead.break`）。
* 1.20.5 より前のバージョンではリードの NBT が `Leash:{UUID:[I;...]}`（大文字始まり）のため、
  `rope/init.mcfunction` と `rope/follow.mcfunction` の書き換えが必要です。

```
hookshot/
├── pack.mcmeta
└── data/
    ├── minecraft/tags/function/   … tick / load への登録
    └── hookshot/
        ├── tags/block/passable.json  … フックが貫通するブロック
        └── function/
            ├── load / tick               … 初期化・毎ティック処理
            ├── use / fire / release      … 使用検知・発射・解除
            ├── give / give_old / uninstall
            ├── hook/   … フック（防具立て）の飛行・着弾・マーカー設置
            ├── pull/   … 引き寄せ（滑らかな移動）
            ├── rope/   … リードとキラキラのロープ
            └── util/   … 後始末・安全装置
```

# ウェブシューター (Spiderweb) — Minecraft データパック

クロスボウ「ウェブシューター」を右クリックすると**クモの糸**（専用の矢）が発射され、
スパイダーマンのように**壁や天井へワイヤーアクションで移動**したり、**MOBかブロックに
3x3x3のクモの巣トラップ**を設置したりできるデータパックです。さらに**左クリック**では
特別な弾を発射し、**命中したクモの巣を塊ごと除去**できます。`hookshot` と同じ
tpステップ移動・見えない台車・キラキラロープの技術をベースに、モード切り替え・
糸の巻き取り/伸ばし・MOB引き寄せ・クモの巣除去などを追加しています。

## 2つのモード（Shiftで切り替え）

未使用時（何も発射していない時）に **Shiftキーを押す**とモードが切り替わります。

| モード | 名前 | 内容 |
| --- | --- | --- |
| 1（初期値） | フックショット | 着弾地点へ引き寄せられる。**MOBに命中した場合はMOBを自分側へ引き寄せる** |
| 2 | 巣づくり | 糸を消費して、着弾したMOBかブロックの周囲 **3x3x3にクモの巣を設置** |

## モード1: フックショットの動作の流れ

| 順番 | 処理 |
| --- | --- |
| 1 | クロスボウを撃つと、実際に発射された「クモの糸」の矢を即座に消し、代わりに透明なフックを視点方向へ射出（1tickに5ブロック／最大100ブロック） |
| 2 | 壁や床に着弾すると、その位置に**マーカーが固定**され、見えない台車にプレイヤーを乗せて滑らかに引き寄せる |
| 3 | **MOBに着弾した場合はそのMOB自身をプレイヤー側へ引き寄せる**（プレイヤーは動かない） |
| 4 | ブロックへの着弾で**マーカーに到達しても自動では解除されず**、そのまま**糸に張り付いた状態**になる |
| 5 | 張り付き中は **Rキーで巻き取り（アンカーへ登る）**、**Shift+Rキーで伸ばす（アンカーから降りる）**ができる |
| 6 | **Spaceキーで解除**すると、その場でレビテーションにより**約5マス打ち上げ**られてから通常の重力に戻る |
| 7 | もう一度クロスボウを使うと、どの状態からでもその場で解除できる（トグル） |

## モード2: 巣づくりの動作

クロスボウを撃つと弾（クモの糸）が飛んでいき、**MOBかブロックに命中した地点を中心に
3x3x3の範囲でクモの巣（`minecraft:cobweb`）を設置**します。空気・水・草花など柔らかい
ブロック（`#spiderweb:passable`）だけを置き換えるため、地形を壊さずにトラップだけを
仕込めます。矢（クモの糸）を1本消費します。

## 左クリック: クモの巣除去弾

ウェブシューターを構えた状態で**左クリック**すると、専用の弾が視点方向へ飛んでいきます
（射程40ブロック、矢は消費しません）。この弾は他の弾と違って**クモの巣だけをすり抜けず**、
命中すると**そのクモの巣と隣接して繋がっている塊をすべて連鎖的に除去**します（最大400
ブロックまで）。壊れたクモの巣は通常どおり糸をドロップします。フックショットで移動中・
張り付き中・巣づくりモードのどれからでも、いつでも使えます。

> **注意:** この機能は「左クリック（攻撃）そのものを検知する」ために、ウェブシューターを
> 手に持っている間だけプレイヤーに追従する見えない当たり判定を使っています。その影響で、
> **ウェブシューターを持っている間は通常の素手攻撃（殴る）ができなくなります**（クモの巣
> 除去弾の発射に置き換わります）。ブロックの採掘には影響しません。

## 導入方法

1. `spiderweb` フォルダを、ワールドの `datapacks` フォルダにコピーします。

   ```
   .minecraft/saves/<ワールド名>/datapacks/spiderweb/
   ├── pack.mcmeta
   └── data/
   ```

2. ワールドに入って `/reload` を実行します。
   `[ウェブシューター] 読み込み完了` と表示されれば成功です。

3. アイテムを受け取ります。

   ```
   /function spiderweb:give
   ```

   ウェブシューター（クロスボウ）1丁と、クモの糸（矢）64本が配布されます。

4. **重要：コントロール設定で「利き手アイテムの交換」を Rキーに割り当ててください。**
   張り付き中の「巻き取り／伸ばす」操作は、この標準キーバインドを流用して
   Rキー入力として検知しているため、割り当てないと反応しません（初期状態ではFキー）。

5. 受け取ったクロスボウで右クリックすると発射されます。操作方法は次のコマンドでも
   確認できます。

   ```
   /function spiderweb:help
   ```

### 操作まとめ

| 操作 | 内容 |
| --- | --- |
| 右クリック | クモの糸を発射（使用中はもう一度でその場を解除） |
| 左クリック | クモの巣除去弾を発射（命中したクモの巣を塊ごと除去。素手攻撃はできなくなる） |
| Shift（未使用時） | モード切り替え |
| R（張り付き中） | 巻き取り（アンカーへ登る） |
| Shift+R（張り付き中） | 伸ばす（アンカーから降りる） |
| Space（張り付き中） | 解除して約5マスジャンプ |

### 旧バージョン（1.21.x）で使いたい場合

`hookshot` と同様に、`pack.mcmeta` の `min_format`/`max_format` を
`"pack_format": 48, "supported_formats": {"min_inclusive": 48, "max_inclusive": 88}`
に戻し、アイテム配布は `/function spiderweb:give_old` を使ってください。
またリードのサウンドID（`item.lead.tied`/`item.lead.untied` → `entity.leash_knot.place`/`.break`）
の戻しも必要です。

### アンインストール

```
/function spiderweb:uninstall
```
を実行してから、データパックのフォルダを削除してください。

## 調整できる数値

## 実装メモ

* **クロスボウでの即時発射** — バニラのクロスボウは矢がないと構えられず、構えて
  離すまで発射されない。そこで実際の弾は普通の矢（`minecraft:arrow`）に
  `custom_data` で「クモの糸」と名付けたものをアンモとして使わせ、
  `minecraft.used:minecraft.crossbow` の統計で発射を検知した瞬間、実際に飛び出した
  その矢を即座にキルして、代わりに見た目上のフック（透明な防具立て）や
  巣づくり弾を同じ向きへ射出している（`hookshot` が釣り竿の`fishing_bobber`を
  キルして防具立てに差し替えているのと同じ考え方）。矢を1本消費するので、
  自然に「糸を消費する」動作になる。クイックチャージIIIを標準装備させ、
  構えから発射までの体感を短くしている。
* **MOBに命中したら「MOBを」引き寄せる** — `hookshot` はMOBに刺さると見えない
  コウモリをそのMOBにrideさせ、プレイヤー側をそこへ引き寄せる作りだった。
  本パックのモード1はこれを反転し、**MOB本体（実在するMOBそのもの）に直接
  タグを付けて**、hookshot の台車ステップ移動と同じ「向き直してから0.25ブロックずつ
  進んで着弾判定」というロジックを、プレイヤーの現在地を目標にMOB自身へ適用している
  （`yank/`以下）。MOBのAIは無効化していないため、通常の行動と綱引きしながら
  引き寄せられる（＝暴れながら引っ張られてくる）。
* **「マーカーに到達しても解除しない」張り付き（attach）** — `hookshot`は到達すると
  即座にレビテーションで打ち上げて解除するが、本パックは到達した瞬間に台車を
  片付け、以後は**プレイヤー自身を「アンカーの真下 sw.len/10 ブロック」の座標へ
  毎ティックtpし直す**ことで宙に固定する（`attach/hold*`）。同じ座標へのtpは
  移動を伴わないため、`hookshot`の実装メモにある「プレイヤー本人を直接tpすると
  カクつく」問題が起きにくい。Rキー（巻き取り）でこの距離を10（1ブロック）ずつ
  減らし、Shift+Rキー（伸ばす）で増やす。伸ばす際は1段下のブロックが
  `#spiderweb:passable` かどうかを毎回チェックし、地面に着く手前で止まる。
* **なぜ「張り付き中」はプレイヤーを台車に乗せていないのか** — バニラの既定
  キーバインドでは、**Sneak（Shift）キーは「乗り物から降りる」キーも兼ねている**
  ため、台車（コウモリ）に`ride`で乗せたままだと、Shift+Rの判定のために
  Shiftを押した瞬間に強制的に降ろされてしまう恐れがある。そこで到達後は
  台車から完全に降ろし、直接tpで位置を固定する方式に切り替えている。
  引き寄せ中（swing-in、台車に乗っている数tick程度の短い区間）はShiftを
  読まないため影響しない。
* **Rキーの検知** — バニラには「Rキー」という概念自体がなく、既定で空いている
  キーもない。そこで常に既定でだけ存在する「利き手アイテムの交換」
  （`minecraft.custom:minecraft.swap_hand`統計、既定Fキー）をユーザー側でRキーに
  割り当ててもらい、それを検知に利用している（`hookshot`が釣り竿の使用回数
  統計を使うのと同じ発想）。Shiftを押しながらRを押しているかどうかは
  `minecraft:entity_properties`述語（`flags.is_sneaking`）で毎ティック判定している。
* **Spaceキーの検知** — 張り付き中はプレイヤーが乗り物に乗っていないため、
  通常のジャンプ入力がそのまま `minecraft.custom:minecraft.jump` 統計に反映される。
  これを利用して、張り付き中だけ「Space＝解除して打ち上げ」として扱っている。
* **Shiftでのモード切り替えとShift+Rの衝突回避** — モード切り替えは
  「未使用中（`sw.active`が付いていない）にShiftを押した瞬間（立ち上がりエッジ）」
  だけに限定し、張り付き中（`sw.attached`は`sw.active`を含む）は判定から除外
  している。逆にShift+Rの「伸ばす」判定は張り付き中にしか意味を持たないため、
  お互いの操作範囲が重ならないようにしている。
* **巣づくりの設置範囲** — `fill ~-1 ~-1 ~-1 ~1 ~1 ~1 minecraft:cobweb replace
  #spiderweb:passable` で、着弾地点を中心とした3x3x3のうち「フックが貫通できる
  柔らかいブロック（空気・水・草花など）」だけをクモの巣に置き換える。石やガラスなど
  硬いブロックはそのまま残るため、地形を破壊せずにトラップだけを追加できる。
* その他（エンティティの後始末・リードのNBT・見えないコウモリでの引き寄せなど）の
  設計は `hookshot` の実装メモと共通。詳細はそちらを参照。
* **左クリック（攻撃）の検知** — バニラには「左クリックした（何も殴っていなくても）」
  ことを直接教えてくれる統計やアドバンスメントが存在しない。そこで1.19.4以降に
  追加された `minecraft:interaction` エンティティ（当たり判定専用の透明な
  エンティティで、攻撃・使用されると `attack`/`interaction` タグに実行時刻が
  自動で記録される）を利用する。ウェブシューターを構えている間だけ、この
  Interactionをプレイヤーの足元に「目の高さを確実に含む大きさ」で追従させておくと、
  攻撃レイの発射位置（目の高さ）が常にこのInteractionの中に入っているため、
  **視線の先に何があっても必ず自分自身のInteractionが最優先でヒットする**
  （`punch/`以下）。左クリックされた瞬間は、Interactionの`attack.timestamp`
  （NBT）が`/time query gametime`で取れる「今」のtick数と一致するかどうかで検知し、
  一致した瞬間にクモの巣除去弾（`fire_clear`→`ball/`）を発射する。
  Interaction自体はダメージ・ノックバック・見た目を一切持たない安全なエンティティ
  なので、他のMOBや地形には何の影響も与えない。
  * 副作用として、**この当たり判定が常に最優先でヒットしてしまうため、
    ウェブシューターを持っている間は通常の素手攻撃がMOBに届かなくなる**
    （左クリックが常にクモの巣除去弾の発射に置き換わる）。ブロックの採掘判定は
    エンティティとは別系統のため影響を受けない。
  * 当たり判定は「ウェブシューターを持っている間だけ」存在し、手放すと即座に
    片付く（`punch/tick.mcfunction` / `punch/remove*.mcfunction`）ため、
    他の武器を持っているときの通常戦闘には影響しない。
* **クモの巣クラスタの除去** — 除去弾が命中した座標を起点に、「そのマスがクモの巣
  なら`air`にして、隣接6方向へ同じ処理を再帰する」という単純な塗りつぶし
  （フラッドフィル）を行う（`webclear/flood.mcfunction`）。除去した場所は
  次の判定で弾かれるため、同じマスを再訪することがなく、無限ループにもならない。
  暴走防止として一度の発射で処理するブロック数に上限（400）を設けてある。

## ファイル構成

```
spiderweb/
├── pack.mcmeta
└── data/
    ├── minecraft/tags/function/   … tick / load への登録
    └── spiderweb/
        ├── predicate/sneaking.json   … スニーク中かどうかの判定
        ├── tags/block/passable.json  … フックが貫通し、巣づくりが上書きするブロック
        └── function/
            ├── load / tick                        … 初期化・毎ティック処理
            ├── use / fire_grapple / fire_web       … 使用検知・モード別の発射
            ├── fire_clear                          … 左クリック: 巣除去弾の発射
            ├── release / release_launch / launch_tick
            ├── mode_toggle / mode_toggle_apply     … Shiftでのモード切り替え
            ├── give / give_old / uninstall / help
            ├── hook/    … モード1: フック（防具立て）の飛行・着弾
            ├── pull/    … モード1: ブロック着弾時の引き寄せ（滑らかな移動）
            ├── attach/  … モード1: 張り付き中の巻き取り/伸ばす/固定
            ├── yank/    … モード1: MOB着弾時のMOB引き寄せ
            ├── web/     … モード2: 巣づくり弾の飛行・着弾・設置
            ├── punch/   … 左クリック検知用の当たり判定（Interaction）の管理
            ├── ball/    … 左クリック: 巣除去弾の飛行・着弾
            ├── webclear/ … クモの巣クラスタの再帰的な除去
            ├── rope/    … リードとキラキラのロープ
            └── util/    … 後始末・安全装置
```
