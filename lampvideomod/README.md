# Lamp Video MOD（レッドストーンランプ動画）

動画を、レッドストーンランプの点灯/消灯（白黒）で再生する Fabric MOD です。
映像の**暗い部分が点灯、明るい部分が消灯**です（線画なら線が光ります）。
データパックと違って、動画データを**外部ファイルから少しずつ読む**ので、`/reload` やワールドを開くときに重くなりません。

## 使い方（jar を入れるだけ）
1. `lampvideomod/dist/lampvideomod-mc26.3.jar` を、`.minecraft/mods/` に入れます（Fabric Loader と Fabric API が必要です）。
2. ワールドに入って、平らな場所で次を実行します。
   ```
   /lampvideo start 360 3
   ```
   画面は、**足元を中心に、地面に水平**に作られます（足元のすぐ下の層を、ランプに置き換えます）。
   **クリエイティブで上空に飛んで、真下を向いて**見てください。北が画面の上、東が右です。音声も鳴ります。

jar には、サンプル動画（360×360、約3分10秒）と音声（速度ごと）、ランプの単色テクスチャが入っています。
**動画ファイルやリソースパック、データパックは要りません。** 画面が水平なので、高さの制限はありません。

## リモコン（右クリックのメニュー）
クリエイティブのタブ「ランプ動画」から **ランプ動画リモコン** を取るか、`/give @s lampvideo:remote` で入手します。
持って**右クリック**するとメニューが開きます（ボタンは、下のコマンドを送るだけです）。

- **大きさ**（360 / 540 / 720）と **向き**（横=水平 / 縦=壁）を選んで、**画面を作る**
- **速度**（1 / 2 / 3 / normal）を選んで、**再生**。**画面を作って再生** で、作成と再生を一度に行います
- **停止**、**画面を片付ける**
- **画面が見える位置へ**: 画面全体が見える位置にテレポート（水平なら真上から真下、縦なら正面の離れた場所）。`/lampvideo view` と同じです
- **チャンク更新**（通常 / 近く同期 / 全体同期）: ボタンを押すたびに切り替わります。`/lampvideochunks normal|sync|all` と同じです（詳しくは下の「チャンクごとのずれ」）
- **ブロック**（光らない専用ブロック / コンクリート / ランプ）、**テクスチャ**（単色 / 元）の切り替え

## 大きさと速度を選ぶ
`/lampvideo start <大きさ> <速度> [名前]`

| 指定 | 内容 |
| --- | --- |
| 大きさ `360` / `540` / `720` | 画面の横のランプの数（正方形の動画なら 360×360 など）。540 と 720 は、初めて使うときに ffmpeg で変換します（時間がかかります） |
| 速度 `1` / `2` / `3` | **全フレーム**を、1tick / 2tick / 3tick ずつ表示。24fps の動画だと、約0.83倍 / 約0.42倍 / 約0.28倍速になります |
| 速度 `normal` | フレームを**間引いて**、元の速さ（等速）で再生 |

音声も、速度に合わせたものが鳴ります。720×720 は、ランプが約52万個、読み込むチャンクが約2000個になるので、とても重くなります。

## 作った画面をそのまま使う
作った画面（位置・大きさ・向き）は保存されます。再起動のあとも、**作り直さずに** `/lampvideo play` で再生できます。
`/lampvideo start` は、保存された画面と大きさ・向きが同じなら、画面を作り直さずにそのまま使います。

## 自分の動画を再生する
`.minecraft/lampvideo/` フォルダ（MOD が自動で作ります）に、動画ファイル（mp4・mkv・webm・mov など）を入れるだけです。

- ワールドを開くと、未変換の動画が**自動で変換**されます（360 用）。`/lampvideo convert` で、その場でも変換できます。
- 変換が終わると、チャットに知らせが出ます。`/lampvideo list` で名前を確認して、`/lampvideo start 360 3 <名前>` で再生します。
- 変換した動画は、`<名前>_<大きさ>.lvf`（例 `mymovie_360.lvf`）として保存されます。名前は、ファイル名から作ります（小文字の英数字と `_`）。
- **変換には ffmpeg が必要です**（PC にインストールして、PATH を通してください。Windows なら `winget install ffmpeg`）。
  ffmpeg がなくても、同梱のサンプルの 360 は再生できます。
- ランプの**単色テクスチャ**は、内蔵のリソースパックです。元の見た目に戻すには `/lampvideotexture normal`、また単色にするには `/lampvideotexture flat`
  （リソースを再読み込みします。リソースパック画面で「ランプ動画: 単色ランプ」を切り替えても同じです）。
- 変換した動画の**音声**を鳴らすには、リソースパック `lampvideo_audio`（`.minecraft/resourcepacks/` に自動で作られます）を一度有効にして、
  F3+T でリソースを再読み込みします。映像だけなら不要です。

## コマンド
| コマンド | 内容 |
| --- | --- |
| `/lampvideo start <大きさ> <速度> [名前]` | 画面を作って（同じ画面があればそのまま使って）、すぐ再生 |
| `/lampvideo setup <大きさ> [名前]` | 画面だけを作る |
| `/lampvideo play [速度] [名前]` | 保存された画面で再生 |
| `/lampvideo stop` / `remove` | 停止 / 画面を片付ける |
| `/lampvideo list` / `status` | 動画の一覧 / 画面と設定の確認 |
| `/lampvideo offset add\|set <ミリ秒>` | 映像を音に対して遅らせる（正）/ 早める（負）。音と映像のずれの微調整 |
| `/lampvideo view` | 画面全体が見える位置にテレポート（高さの上限で、全体が入りきらないことがあります） |
| `/lampvideochunks normal` / `sync` / `all` | チャンク更新の方式: 通常 / 近くを同期 / 画面全体を同期（クライアント側のコマンド） |
| `/lampvideo convert` | フォルダの未変換の動画を、いま変換する |
| `/lampvideo set layout flat\|wall` | 画面の向き: `flat`（水平。既定）/ `wall`（縦。足元が左下の角。南側から北を向いて見る。高さに注意） |
| `/lampvideo set block nolight\|solid\|lamp` | 画面のブロック: 光らない専用ブロック（既定。ランプと同じ見た目で、光の計算が要らずいちばん軽い）/ 白と黒のコンクリート / レッドストーンランプ（光る。重い） |
| `/lampvideotexture normal` / `flat` | ランプのテクスチャを、元に戻す / 単色にする（クライアント側のコマンド） |

コマンドの権限は設定していません。サーバーで使う場合は、オペレーター以外も実行できます。

## 画面がチャンクごとにずれて見えるとき
画面は 16×16 ブロックの区画（チャンクの縦の1/24）ごとに描き直されるため、描画が追いつかないと、チャンクの境目でずれて見えることがあります。
ブロックで作る画面では、**全体を完全に同時にする**ことは保証できません。ずれを減らす手順（効果の大きい順）:

1. 画面のブロックを **光らない専用ブロック**（既定）か `solid` にして、画面を作り直す（リモコンの「ブロック」ボタン → 「画面を作って再生」）。
   レッドストーンランプは、点灯と消灯のたびに**光の計算**（サーバーとクライアントの両方）が走り、その処理が数フレームにまたがって、チャンクごとに順番に見える原因になっていると考えています。
   白と黒のコンクリートは光を出さないので、この計算が要りません。
2. **チャンク更新を「全体同期」にする**（リモコンのボタン、または `/lampvideochunks all`）。
   バニラは、カメラから約27ブロック以内の区画だけを、同じフレームで作り直し（設定「チャンクビルダー」=完全ブロッキングのとき）、遠い区画は別スレッドで作り直すため、作り終わる順番がばらばらになります。
   「全体同期」は、この MOD が描画処理（`LevelRenderer#compileSections`）に割り込んで、**動画の再生中だけ**、画面のすべての区画を同じフレームで作り直させます。重くなる（再生中のカクつき）代わりに、全体が同時に切り替わるはずです。
   割り込み先が見つからなくても、ゲームは落ちません（その場合は、何も起きません）。「近く同期」は、設定を切り替えるだけです。
   ※ 描画処理の書き換えは、実機で確認できていません。
3. 画面のすぐ上で見る（`/lampvideo view` のあと、画面に近づく）。
4. 速度を遅くする（`2` や `3`）。1フレームの間隔が長いほど、描画が追いつきます。

## 音と画面の同期
画面は、サーバーの tick の数ではなく、**実際の経過時間**に合わせて進めます。サーバーが重くて遅れても、足りない分のフレームをまとめて進めて、音（クライアントで実時間どおりに鳴る）に追いつきます（遅れが大きいときは、フレームが飛びます）。
ゲームの一時停止中は、映像の時計も止まります。
音の開始が少し遅れて、映像が先に進んでしまうときは、`/lampvideo offset add 50` で、映像を遅らせてください（`add -50` で早めます。`offset set <ミリ秒>` で直接指定）。リモコンのメニューにもボタンがあります。再生中でもすぐ効きます。

### 同期がずれるときの確認
- `/lampvideo status` を再生中に実行すると、「映像の遅れ（いま／最大）」「飛ばしたフレーム数」「1回の更新にかかった最大の時間」が出ます。
  サーバーが重くて追いつけないときは、遅れが大きくなり、フレームが飛びます（飛ばして、音に追いつきます）。
- 時計と音は、**最初のフレームを画面に出し終えてから**始まります。ゲームの一時停止中は、映像の時計も止まります。
- `/lampvideochunks status`（クライアント側）で、チャンクの割り込みが実際に呼ばれたかが分かります。「割り込みの呼び出し」が 0 回のままなら、割り込みが適用されていません。

## 音声
音声は、サーバーが各プレイヤーのクライアントに通信を送り、**プレイヤーに付いてくる音**として鳴らします（位置に関係なく、飛び回っても音量が変わりません）。
そのため、画面を見る**全員がこの MOD を入れている**必要があります。再生中に入ってきたプレイヤーには、鳴りません。

## ビルド
GitHub の Actions（`Build lampvideomod`）で、jar をビルドして `lampvideomod/dist/` に保存します。
手動実行のとき、Minecraft のバージョンを指定できます（既定 26.3）。

## 動画ファイル（.lvf）を直接作る
変換は MOD が自動でやりますが、Python のツールでも作れます。
```
pip install numpy pillow     # ffmpeg も必要
python3 ../lampvideo/make_lvf.py input.mp4 --out out --name myvideo --width 360 --hold 3
```
できた `myvideo.lvf` を、`myvideo_360.lvf` という名前にして `.minecraft/lampvideo/` に置くと、`/lampvideo start 360 3 myvideo` で再生できます。

## 仕組み（メモ）
- ランプは、隣のブロックに通知しない設定（`setBlock` のフラグ2）で `lit` を直接切り替えます。
  無電力で点灯したランプが約4tick後に勝手に消える現象は、隣への通知があるときだけ起きるので、これで防げます。
- フレームは、前のフレームとの差分の長方形だけを持ちます。100フレームで全面を1周描き直し（帯状に少しずつ）、書き込みに失敗しても直ります。
- 手前に明るさ15の光源ブロックを敷いて、ランプ面の明るさを一定にします（明暗のムラ防止）。
- 形式は `src/main/java/com/lampvideo/LvfVideo.java` の説明を参照してください。

> 実際の Minecraft 26.3 では、まだ動かしていません。ビルド（コンパイル）は成功しています。動かないところがあれば、教えてください。


## チャンクの同期更新の範囲

「画面全体を同期」は、再生中、画面を含む区画(まわり16ブロック)だけを同期で作り直します。画面と関係ない区画は標準のままなので、画面全体を同期にする負荷は画面の分だけです。Sodium など描画を置き換える MOD を入れていると、この割り込みは効きません（Sodium を外してください）。

## メディアディスプレイ(開発中・段階 3)

クリエイティブタブ「ランプ動画」の **ディスプレイ**(1枚)と **大型ディスプレイ(枠なし。ふつうに使うと1枚、しゃがんで使うと 7x4 を一度に置く)** を、壁・天井・床に置く。右クリックで操作画面が開く。

- 隣り合う同じ向きのディスプレイは、自動で1枚の大画面につながる(つながった辺の枠が消える)。大型ディスプレイは、7x4 を一度に並べる。操作は、どのパネルを右クリックしても、グループ全体に効く(左上のパネルが「親」)。
- 動画・音楽は、`.minecraft/lampvideo/media/` に入れる(mp4 / mkv / webm / mov / avi / mp3 / ogg / wav / flac / m4a)。ffmpeg が必要。
- モード: カラー / モノクロ(緑・アンバー・グレー) / ランプ風(ドット絵)。
- 操作: 再生 / 停止 / 一時停止・再開 / 10秒進める / 10秒戻す。Esc のメニューを開いている間は、その端末で映像も音も止まる(閉じると続きから)。
- 音と映像は、音声を基準の時計にして合わせる(スピーカーが実際に再生したサンプル数から、いまの位置を出し、その時刻のコマを出す。遅れたコマは飛ばし、早すぎるコマは待つ)。耳に届く音が映像より遅れるときは、`/lampvideoav <ms>`(-500〜500、プラスで映像を遅らせる)で端末ごとに補正する。
- 映像は、ブロックの描画(BlockEntityRenderer)が1枚のテクスチャとして描く。チャンクの再構築もブロック更新も要らない。Sodium とも干渉しない見込み(実機では未確認)。
- サーバーが持つのは「ファイル名・モード・状態・位置」だけ。デコードと音声は各クライアントが行う。
- 距離による音量の減衰(32ブロックで無音。大画面は大きさの分だけ遠くまで)、64ブロックより遠いと再生を止める(近づくと途中から)。

### PC・キーボード・管理パネル・リモコン(段階 3)

- **パソコン**: 置いた人が持ち主になる。右クリックで操作画面。持ち主が、パスワードの設定/解除と、近く(24ブロック)の画面の登録/解除をする。登録された画面は、PC の管理下になり、まとめて再生・停止・一時停止・シーク・モード変更ができる。管理下のディスプレイは、直接は操作できない。
- **キーボード**: 近く(16ブロック)の一番近い PC の操作画面を開く。
- **管理パネル**(アイテム。リモコンの進化版。右クリックで、いまいる場所の近くを対象に開く): 近く(48ブロック)の PC と画面の一覧を出して、画面を1枚ずつ好きな PC に接続/解除し、画面ごとの名前・音量・ミュートを設定する。選んだ PC につながる画面を、まとめて停止・一時停止できる。PC の操作画面も、ここから開ける。
- **スタンド型ディスプレイ**: 地面に立てて置く1ブロックの卓上モニター。8方向(斜めも)に置け、置くと、プレイヤーの方を向く。東西南北の向きに置いたスタンドは、同じ向きの普通のディスプレイ(枠あり)を、上と左右に置くと、つながって画面が拡張される(スタンドの下側にはつながらない)。斜めのスタンドは、小さめに描かれ、単独で使う。
- **ディスプレイの向き**: 床・天井に置いたとき、画面の上は、置いたプレイヤーが向いている方向になる(壁では真上)。
- **画面の比率**: 枠のある普通のディスプレイは、単独だとパソコンのモニターの比率(16:9)で、上下は枠を太くせず、空間を開ける(外形が 16:9 のモニターになる)。隣とつながった辺は、枠が消えて、ブロックの端まで広がる。スタンドを含むグループは、スタンドの画面の高さにそろう。枠なしの大型ディスプレイは、ブロックいっぱいが画面。映像は、画面の見える範囲と同じ比率の大きさで作られ、映像の全体が画面に収まる(余りは黒)。
- **リモコン**(ランプ動画リモコン): しゃがんで使うと、近く(32ブロック)の PC の操作画面を開く。ふつうに使うと、これまでのランプ動画のメニュー。
- **パスワード**: ソルト付き SHA-256 のハッシュだけを保存する。持ち主以外は、パスワードを入れて解錠するまで操作できない(間違えると2秒待たされる)。解錠済みの人は、サーバーを動かしている間だけ覚えられ、パスワードを変えると解除される。
- 段階 4 以降(予定): スタンド型、スピーカー・ヘッドホン、YouTube、プロジェクター、チップチューン。

### 操作の仕組み(整理)

- ディスプレイは、右クリックでは操作できない。**PC に接続**(管理パネルの一覧、またはしゃがんで管理パネルでディスプレイを右クリック)しないと、再生できない。操作は、**キーボード・管理パネル・リモコン**からだけ。PC 本体を右クリックしても、操作画面は開かない。
- **キーボード**は、PC か、PC に登録された画面の「真ん中の一番下」から **8 ブロック以内**で使える。
- **管理パネル**をしゃがんで持ち、ディスプレイ(スタンドでも普通のディスプレイでも、向きが違っても、斜めでも)を右クリックすると、近くの PC に接続(すでに接続されていれば解除)する。
- 接続した画面が壊されたら、接続から自動で外れる(隣のパネルが残っていれば、そちらに引き継ぐ)。
- ディスプレイに照準を合わせても、当たり判定の黒い枠は出ない(当たり判定自体はあり、壊せて、ブロックとして置ける)。

### 段階 4: スピーカー・ヘッドホン、連結の拡張

- **スピーカー**(接続しないと、音は流れない。ヘッドホンを着けていれば、スピーカーなしでも聞こえる): PC に接続すると、その PC が再生する音が、スピーカーの位置から聞こえる。距離で小さくなり(24ブロックで無音)、聞く人の向きに合わせて左右に振り分けられる(ステレオ)。スピーカーが接続されていない画面は、無音になる。音量は、スピーカーごとに、管理パネルの「一覧: スピーカー」で変えられる(名前も付けられる)。接続は、管理パネルの一覧から、または、管理パネルをしゃがんで持って、スピーカーを右クリック(もう一度で解除)。(「近くの画面を登録」は、なくなった。)スピーカーは1台の PC に16台まで。壊されたスピーカーは、自動で外れる。
- **ヘッドホン**: 持ち物画面で、兜のスロットにカーソルを合わせると、その横に出てくる、ヘッドホン専用のスロットに入れる(右クリックでも着けられる)。兜の欄には入らない。着けると、256ブロック以内の再生中の画面が、スピーカーがなくても、距離で小さくならず、中央ではっきり聞こえる(音量は、画面ごとの設定に従う)。頭には、ヘッドホンが見える(兜を着けているときは、兜を優先)。
- **向きが違うディスプレイの連結**: ディスプレイを置いたとき、画面の面の中(上下左右)で隣り合うディスプレイがあれば、そのディスプレイの向きに合わせて置かれ、つながる(床・天井・壁をまたいでも、斜めでも)。スタンドの横にも、同じ向きに合わせて、つながる。
- **斜めの連結**: 斜めのスタンドの、斜めの隣(x と z が 1 ずつずれた位置)にディスプレイを置くと、斜めの向きに合わせて、つながる。斜めの画面は、1 枚の幅がブロックの対角線(√2 倍)になり、斜めに並べても、すき間なく 1 枚になる。
- **右クリック**: ディスプレイと PC は、右クリックしても何も起こらない。
- **キーボード**: テンキーをなくして、キーを大きくした。
- 段階 5 以降(予定): YouTube、プロジェクター、チップチューン(ノートブロック音)モード。

### 設定画面を開いている間

管理パネル・PC の操作画面・リモコンのメニューは、開いている間も、ゲームを一時停止扱いにしない(1人用でも、サーバーが動き続けて、ボタンの操作がすぐに反映される)。以前は、1人用で、設定を開いている間にサーバーが止まって、操作が返ってこず、何もできなくなることがあった。

### 軽量化と、自動の位置合わせ

- 映像の1コマ分の配列(1枚が数MB)を使い回して、毎フレームのメモリの確保をなくした。連結の計算(隣のパネルを何十回も調べる)は、10 tick に 1 回にした。ffmpeg の縮小は、軽い方式(bilinear)にした。
- **自動の位置合わせ**: 音声の再生位置が、サーバーの時刻から出した本来の位置から 0.3 秒以上ずれたまま 1.5 秒続いたり、映像のデコードが 0.5 秒以上追いつかなくなったりしたら、自動で、本来の位置から始め直す(始め直しは 4 秒に 1 回まで)。
- **ワールドの保存中に固まる問題**: 2 つの原因を直した。(1) ディスプレイが取り除かれるとき(チャンクの解放中を含む)に、読み込まれていないチャンクのブロックを調べて、読み込みを待って止まる。いまは、サーバーを止めている間は何もせず、読み込み済みのチャンクだけを、待たずに調べる。(2) ワールドを抜けるとき、音声の出力を止める処理が、書き込み中のスレッドと衝突して止まる。いまは、別のスレッドで片付ける。

## ステージ6: スピーカー音モード / プロジェクター
- スピーカー設定(管理パネル)で音モードを選択: 普通 / 効果音(音符ブロック系なし) / 音符ブロック。
  効果音・音符ブロックは音声を解析し、バニラのサウンドで再合成します(約50ms刻み)。
- プロジェクター: 壁に映像を投影します。
- 音ズレ対策: 音声スレッドがラインを所有し、独自クロック(書き込みフレーム−キュー残)をマスターにしました。2回目以降の再生で出ていたズレの修正です。
- クリエイティブ: インベントリの「聴」ボタンでヘッドホンの装着を切り替えられます。

## 主旋律ファイル(音符ブロック・効果音用)
曲の自動解析は精度が低いので、主旋律(歌うときの音程)のファイルを作って読み込ませられます。

1. `python lampvideomod/tools/melody_tool.py 曲.mp3`(mp4 も可。`--separate` で歌声だけを先に取り出す。要 demucs)
   - 必要なもの: Python、numpy、ffmpeg。外部サイトには何も送らず、この PC の中だけで処理します。
2. できた `曲.melody.json` を `.minecraft/lampvideo/`(または `lampvideo/media/`、`lampvideo/melody/`)に入れる。
3. 同じ名前の曲(`曲.mp3`)を再生すると、音符ブロック/効果音のスピーカーは、この旋律を鳴らします。ファイルがなければ、従来どおり自動解析します。

JSON はテキストなので手直しできます(`t`=開始ms、`d`=長さms、`n`=MIDI ノート番号、`v`=強さ)。

### 効果音・音符ブロックのタイミング
音が映像より先に鳴るときは、`/lampvideosynth <ms>`(例: `/lampvideosynth 250`)で遅らせます。すぐ反映され、保存されます(初期値 120)。
`.melody.json` に `"offsetMs": 数字` を足して、その曲だけ前後にずらすこともできます。

### 映像が遅れるとき
映像のデコードが実時間に追いつかない端末では、映像が音より遅れ続けます。0.7秒以上の遅れが2.5秒続くと、自動で画質(大きさとコマ数)を下げて、始め直します。
`/lampvideoquality <0〜3>`(0 = 細かい、3 = 軽い)で、手動でも変えられます(保存されます)。

## トロッコムービー
- アイテム「トロッコムービー」をブロックに使うと、向いている方向に、長さ 200 の通路(石レンガの壁と床、天井なし、幅 3、真ん中にレール)ができます。
- 通路の手前に、特殊ブロック(持ち物にはありません)、上にボタン、手前に選んだ曲を出す看板があります。特殊ブロックを右クリックして動画を選び(`.minecraft/lampvideo` の動画)、ボタンを押すと、トロッコに乗って、左の壁を向きます。1秒後に走り出し、壁の額縁に、動画の1コマずつのマップが出ます。
- 速さは1秒に 30 ブロック。動画も 30 コマ/秒にして使うので、動画は等倍で流れます(音はありません)。
- マップは全面を使います(縦横比は、正方形に引き伸ばします)。色は、マップの色の表から選び、ディザで細かく見せます。
- 通路は、動画の長さに合わせて、先へ先へと伸びます(最初の 200 ブロックのあとは、トロッコの 64 ブロック先まで作り、40 ブロック後ろは消します)。テレポートはしません。降りると(または動画が終わると)、スタートに戻り、伸ばした部分と額縁は消えます。
- 動画は、サーバー側の ffmpeg で読みます(1人用は、そのままで動きます)。
